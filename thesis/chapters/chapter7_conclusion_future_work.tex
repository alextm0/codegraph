\chapter{Future Work and Conclusion}
\label{ch:conclusion}

This thesis addressed the challenge of repository-level code retrieval by developing a system that combines lexical anchoring with structural graph propagation. Based on the findings discussed in \cref{ch:evaluation,ch:discussion}, this final chapter outlines the most promising directions for future research and summarizes the core contributions and findings of this work.

% =============================================================================
\section{Future Work}
\label{sec:future-work}
% =============================================================================

The failure modes and technical boundaries identified in the preceding chapters suggest five primary directions for extending the CodeGraph architecture.

\paragraph{LLM-based Seed Extraction.} 
To address semantic gap failures, future work should investigate using an LLM to preprocess issue descriptions. Instead of relying on raw text, an LLM could suggest likely module names or technical entities that augment the BM25 seeds. This would improve the translation of abstract symptoms into code identifiers, though it introduces a trade-off between higher recall and increased compute cost.

\paragraph{Embedding-based Retrieval as Seed Source.} 
A more systematic way to address vocabulary mismatch is through dense retrieval. By using vector embeddings for both code and task descriptions, we could propose seed nodes that do not share any exact keywords with the query. This would create a powerful hybrid architecture consisting of a semantic front-end for initial discovery and a structural graph amplifier for high-fidelity ranking.

\paragraph{Selective Structural Features.} 
Our experiments showed that global structural additions like directory-level edges can be harmful. Future work should explore more targeted features, such as adding co-location edges only within small, cohesive directories or incorporating co-change histories from version control. These soft signals could capture dependencies that are invisible to static analysis.

\paragraph{Multi-language and Multi-repo Support.} 
The use of Tree-sitter makes extending CodeGraph to other languages feasible. Supporting TypeScript and JavaScript is a natural next step given their prevalence in modern agent tasks. Furthermore, extending the graph schema to handle cross-repository dependencies or monorepos would allow the system to be applied to larger, more complex industrial systems.

\paragraph{End-to-end Agent Evaluation.} 
Finally, future work should move from measuring retrieval quality to measuring task resolution. Plugging CodeGraph into a complete SWE-bench resolution pipeline would show how often an agent produces a correct patch with and without structural context. This would test the link between retrieval improvements and end-user productivity.

\section{Conclusion}
\label{sec:final-conclusion}
% =============================================================================

\paragraph{Summary of Contributions.}
This thesis introduced CodeGraph, a graph-based retrieval system designed specifically for AI coding agents. We developed a unified pipeline that pairs lexical seed extraction with Personalized PageRank over a deterministic code dependency graph. Our work identified seed extraction as the primary bottleneck in code retrieval and demonstrated how a systematic approach to seed quality can unlock the potential of graph-based ranking.

\paragraph{Final Results and the Structural Limit.}
The research improved retrieval performance over the initial baseline and exposed a clear boundary. When seeds land in the reachable region of the graph, seed and ranking refinements are effective. When the target file is semantically disconnected from the task description or structurally isolated from the seed set, PPR has little signal to recover it. This finding suggests that the retrieval ceiling is determined more by seed mapping and graph connectivity than by further tuning of the ranking algorithm.

\paragraph{Broader Implications.}
The core conclusion of this research is that explicit graph structure is a useful signal for code retrieval. Lexical methods remain necessary because they connect a task description to possible starting points. Graph propagation then uses code relationships to rank the surrounding entities. For repository-level tasks, this combination provides a more reliable retrieval path than text matching alone.

The results also point toward hybrid retrieval as the most practical direction. Graph algorithms provide precision and inspectability, but they need better semantic bridges from natural language to code identifiers. Future systems should combine semantic retrieval or LLM-assisted seed extraction with structural ranking, while preserving the deterministic graph layer that makes failures easier to inspect.
