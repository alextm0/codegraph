\chapter{Evaluation and Results}
\label{ch:evaluation}

We evaluate CodeGraph on SWE-bench Lite, a benchmark of 300 real GitHub issues paired with human-written fixes across 12 popular Python repositories. The task is file-level retrieval: given only a natural-language issue description and a repository, the system must rank source files by relevance and place the file modified in the human patch near the top of that list.

The optimal configuration reaches 74.0\% Recall@10, a 24.3 percentage point improvement over the competitive BM25-only baseline. This chapter tells the story of how the system reached that result. Rather than presenting the final numbers in isolation, we trace the iterative engineering process: a diagnostic discovery about the bimodal structure of retrieval failures led to a Seed-First strategy that produced the dominant share of all performance gains.

\subsection{Metrics and Protocol}
\label{sec:eval-metrics}

We evaluate retrieval at the file level, reporting three complementary metrics:
\begin{itemize}
    \item \textbf{Recall@$k$ (R@$k$):} The fraction of issues where the target file appears in the top-$k$ results. R@10 is our primary metric.
    \item \textbf{Mean Reciprocal Rank (MRR):} The average of $1 / \text{rank}$ for the target file, sensitive to rank quality.
    \item \textbf{Zero-recall count:} The number of issues where the target file does not appear in the top-10 results.
\end{itemize}

\subsection{Baselines}
\label{sec:eval-baselines}

We compare CodeGraph against three baselines:
\begin{itemize}
    \item \textbf{Random:} Establishes the performance floor.
    \item \textbf{BM25-only:} A sparse lexical retriever that establishes the lexical foundation without structural propagation.
    \item \textbf{One-hop ego graph:} An unranked structural baseline that returns all neighbors within one hop of the seeds.
\end{itemize}

This trajectory serves as evidence for the Seed-First strategy. The gains are driven by three interventions: algorithm refinement (+18.7pp) from switching to uniform restart; seed selection improvements (+11.6pp) including compound tokenization and IDF weighting; and budget adjustment (+1.7pp) by increasing $k$ to 30.

\subsection{Seed Selection Improvements}
\label{sec:eval-seeds}

The Seed-First strategy acknowledges that improving seeds is more effective than refining the ranking algorithm. The implementation uses five interventions to implement this strategy:
\begin{enumerate}
    \item \textbf{Uniform PPR Restart:} Assigns equal restart mass to all seeds, letting graph topology resolve competition between them.
    \item \textbf{Compound Tokenization:} Decomposes CamelCase and snake\_case identifiers, allowing natural-language queries to match code identifiers.
    \item \textbf{Expanded BM25 Corpus:} Includes file paths, class names, and qualified names in the index.
    \item \textbf{Inverse-Frequency Entity Weighting:} Penalizes ambiguous seed names (e.g., \texttt{update}) proportional to their frequency in the graph.
    \item \textbf{Candidate Budget Optimization:} Increases $k$ to 30 to recover instances ranked just outside the initial threshold.
\end{enumerate}

\section{Error Analysis}
\label{sec:eval-diagnostics}
% ============================================================

CodeGraph's retrieval failures are bimodal: the target file either ranks in the top-5 or does not appear in the top-10 at all. This section explains this pattern and classifies the remaining 78 failures into a structural taxonomy.

\paragraph{Bimodal Rank Distribution.}
For most issues, the target file either ranks in the top-5 or does not appear in the top-10. Only 15 out of 300 instances (5\%) fall in the intermediate band (ranks 6--10), as shown in \cref{fig:bimodal}. This reveals that PPR ranking is not the primary bottleneck: when the system identifies a useful starting point, it almost always ranks the target highly. The dominant failure mode is reachability: if no seed lies on a structurally connected path to the target, PPR has no signal to propagate there.

    \caption{Bimodal rank distribution for the initial configuration. Instances land almost exclusively in Rank 1--5 or outside the top~10. This implies that reachability, not ranking, is the primary constraint.}
    \label{fig:bimodal}
\end{figure}

\paragraph{Codebase Structure and Retrieval Success.}
Performance varies by repository structure, as shown in \cref{tab:per-repo}. Subpackage-heavy repositories like scikit-learn (9\% failure) and matplotlib (13\%) yield high recall because their cohesive module clusters reinforce task-specific seeds. In contrast, repositories with large, heterogeneous directories like Django (27\%) or SymPy (31\%) create more difficulty: a single directory often mixes distinct concerns without explicit internal edges, limiting propagation. Plugin-driven architectures, such as Pylint (83\% failure), present an illustrative example of the limits of static analysis: many dependencies are registered dynamically and remain invisible to the graph.

\paragraph{Structural Failure Taxonomy.}
An analysis of the 78 zero-recall instances identifies two distinct failure modes (\cref{fig:taxonomy}):
\begin{itemize}
    \item \textbf{Connectivity Gaps (40 instances):} Occur when seeds land in the correct part of the codebase but no explicit edge connects them to the target file. This reflects the inherent limitation of static analysis for files that are logically related but structurally isolated.
    \item \textbf{Semantic Gaps (38 instances):} Arise from abstract natural-language descriptions with no lexical overlap with source code identifiers. Without a lexical match, the BM25 stage cannot place any seed in the relevant neighborhood.
\end{itemize}

\section{Ablations and Sensitivity Analysis}
\label{sec:eval-ablations}
% ============================================================

This section justifies our design decisions through controlled ablation studies, measuring the individual contribution of each component to the final performance.

\subsection{Algorithm Selection: Uniform vs. Weighted Restart}
\label{sec:eval-ablation-algorithm}

The most consequential choice is the restart distribution. Switching to uniform restart raises R@10 from 42.0\% to 60.7\% (+18.7pp). While weighting by confidence amplifies false positives from ambiguous seeds, uniform restart lets graph topology resolve where probability accumulates. This is consistent with the bimodal observation: the ranking function works correctly once given a useful starting point.

\subsection{Hyperparameter Sensitivity: Budget and Damping}
\label{sec:eval-ablation-sensitivity}

We sweep over the candidate budget $k$ and the PPR damping factor $d$ to characterize sensitivity.
\begin{itemize}
    \item \textbf{Candidate Budget ($k$):} Increasing $k$ from 20 to 30 yields a 1.7pp gain. Further increases to 50 provide no additional gain, as the structurally reachable neighborhood is already covered.
    \item \textbf{Damping Factor ($d$):} The system is robust between $d=0.55$ and $d=0.80$. We use $d=0.70$ for consistent performance. Lower values cause excessive diffusion, while higher values confine the random walk too close to the seeds, limiting its reach.
\end{itemize}

Connectivity Gaps arise from missing explicit edges, and Semantic Gaps arise from lexical mismatch. Together, they account for all 78 zero-recall instances and establish the boundary conditions that \cref{ch:discussion} interprets and \cref{ch:conclusion} addresses through future work.
